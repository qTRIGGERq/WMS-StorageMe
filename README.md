# WMS-StorageMe: Информационная система управления складом

**Курсовой проект по дисциплине:** «Объектно-ориентированное программирование с использованием интерпретируемых языков»  
**Учебное заведение:** РТУ МИРЭА (2-й курс)  
**Язык разработки:** Python 3.10+  
**Архитектурный паттерн:** Многослойная архитектура (Layered / 3-Tier Architecture), Repository Pattern, Domain Model  

---

## 📌 1. Цель и назначение работы

Целью курсового проекта является разработка модульной консольной информационной системы класса **WMS (Warehouse Management System)** для автоматизации складских операций:
- Учет номенклатуры товаров (наименование, категория, цена, количество, физическое местоположение на складе).
- Регистрация движений запасов (приход, отгрузка, списание, удаление) с формированием неизменяемого аудиторского следа.
- Контроль неснижаемого остатка (low stock alert) и расчет аналитических показателей (суммарная капитализация склада, распределение по категориям, самые дорогие и массовые позиции).
- Надежное сохранение данных в формате JSON с защитой от повреждений (атомарная запись через временный файл).

## 💎 3. Применение принципов ООП

| Принцип ООП | Где реализован в проекте |
|-------------|--------------------------|
| **Инкапсуляция** | Закрытые атрибуты (`_name`, `_quantity`, `_price` и т.д.) и публичный интерфейс через декораторы `@property` и `@<field>.setter` с обязательной валидацией входных типов и диапазонов (защита от отрицательных цен и остатков). |
| **Наследование** | Все доменные сущности наследуются от `BaseEntity`, наследование исключений от базового `WMSException`, наследование `JsonWarehouseRepository` от `BaseWarehouseRepository`. |
| **Полиморфизм** | Полиморфные методы сериализации `to_dict()`, переопределение строкового представления `__str__()` и `__repr__()`, полиморфное использование контракта `BaseWarehouseRepository` сервисом `WarehouseService`. |
| **Абстракция** | Использование абстрактных классов `abc.ABC` и декораторов `@abstractmethod` для формализации контрактов сущностей (`BaseEntity`) и хранилищ данных (`BaseWarehouseRepository`). |

## 🛡️ 4. Реализация принципов SOLID

1. **Single Responsibility Principle (SRP):**
   - `Product` отвечает только за данные и валидацию товара.
   - `JsonWarehouseRepository` отвечает исключительно за дисковый ввод-вывод в JSON.
   - `WarehouseService` содержит только правила бизнес-логики (проверка уникальности, формирование транзакций, расчет остатков).
   - `WarehouseApp` отвечает за консольный ввод/вывод и форматирование сообщений пользователю.
2. **Open/Closed Principle (OCP):**
   - Возможность добавить новый тип хранилища (например, `SqliteWarehouseRepository`), реализовав `BaseWarehouseRepository`, без изменения кода `WarehouseService`.
3. **Liskov Substitution Principle (LSP):**
   - Любая реализация `BaseWarehouseRepository` может быть подставлена в сервис без нарушения его корректности.
4. **Interface Segregation Principle (ISP):**
   - Интерфейсы классов минималистичны и содержат только необходимые методы.
5. **Dependency Inversion Principle (DIP):**
   - Высокоуровневый модуль `WarehouseService` не зависит от деталей `JsonWarehouseRepository`, а зависит от абстракции `BaseWarehouseRepository`. Зависимость внедряется через конструктор (Dependency Injection).

## 📊 6. Функциональные возможности консольного меню

1. `➕ Создать новый товар` — регистрация товара с валидацией наименования, цены, остатка, категории и локации; фиксация начального движения.
2. `📦 Просмотреть каталог товаров` — форматированный вывод каталога с расчетом стоимости каждой позиции и общих итогов склада.
3. `📝 Изменить количество (приход / отгрузка)` — изменение остатка с указанием причины (накладная, инвентаризация и др.) и автоматической записью транзакции (`INCREASE` / `DECREASE`).
4. `✏️ Редактировать параметры товара` — частичное или полное обновление атрибутов товара.
5. `🔍 Поиск товаров по наименованию` — регистронезависимый поиск по подстроке.
6. `📋 Журнал аудита движений запасов` — хронологический просмотр операций (тип операции, товар, количество, причина, дата/время).
7. `📊 Аналитика и статистика склада` — расчет общих метрик, распределение по категориям, выявление самой дорогой и массовой позиции, оповещение о критических остатках (< 10 шт.).
8. `🗑️ Удалить товар из системы` — снятие позиции с учета с сохранением записи в истории аудита.
